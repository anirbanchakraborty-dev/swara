# Swara v0.1.1

A release with one fix. The grammar, the language server and the plugin otherwise behave exactly as in v0.1.0.

## Fixed

`swara info` and `:checkhealth swara` now name the grammar commit the program was built from. Every v0.1.0 binary reported `local` there instead. The build read the grammar's commit from `Cargo.lock`, which records a commit only for a git dependency, and every build, the release included, compiles the grammar from a checkout beside Swara's own. The build now asks git for the commit of that checkout, and still reports `local` for a grammar folder that is not a git checkout.

## Unchanged

The grammar is still `tree-sitter-lilypond` v0.1.0, commit `53293e9c5ddb55c033b9068842b158ed01bb74cb`, so the grammar revision in a Neovim configuration stays at `v0.1.0`. The five platform archives, `SHA256SUMS` and the checksum check before unpacking are the same as in v0.1.0, and every known limit in the v0.1.0 notes still applies.

## Upgrading

The plugin downloads v0.1.1 the first time a LilyPond file opens after the plugin updates. A `swara` found on `PATH` is used instead of the download, and the plugin does not compare its version, so a copy installed from the Homebrew tap needs `brew upgrade swara`. The README now describes that install.
